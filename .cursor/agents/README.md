# Agents 目录说明

本目录存放 **Cursor 子代理（Subagents）** 定义。主 Agent 可将验证、调试等专项任务委派给这些子代理，由它们在独立上下文中执行并返回结果。

---

## 当前子代理

| 文件            | 名称     | 说明                                                                                                                                                   |
| --------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **verifier.md** | verifier | 验证已完成的工作：检查实现是否存在、功能是否正常，运行测试或验证步骤，查找遗漏的边界情况；报告通过项与需修复项。适合在任务标记为「完成」后做收尾验证。 |
| **debugger.md** | debugger | 调试专家：捕获错误与堆栈、确定复现步骤、定位根因、实施最小化修复并验证。适合在遇到错误或测试失败时调用。                                               |

---

## 使用方式

- Cursor 会识别 `.cursor/agents/` 下的 `.md` 文件为子代理。
- 主 Agent 在对话中根据任务类型选择委派（如「验证一下刚才的修改」→ verifier，「这段报错帮我查原因」→ debugger）。
- 子代理执行结束后，结果可由 Hooks（如 `save-subagent-result.js`）保存到 `reports/subagents/`，便于复查。

---

## 子代理文件格式

每个子代理为一个 Markdown 文件，建议包含：

- **YAML front matter**：`name`、`description`，可选 `model`（如 `Inherit` 表示继承主会话模型）。
- **正文**：该子代理的角色说明与调用时的行为指令（步骤、输出格式等）。

新增子代理时在本目录添加新的 `.md` 文件即可，Cursor 会自动识别。
