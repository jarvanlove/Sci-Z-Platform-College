# 产教研智能体 - 需求与设计

## 1. 需求描述

### 1.1 业务目标

在 **AI 智能体工作台**（实践页）增加 **产教研智能体**，面向高层领导提供「申报课题 → 匹配团队 → 查看明细 → 分发项目」的决策支持：

- **触发**：领导在智能体页面输入 **申报课题**（课题名称、关键词或简要描述）。
- **系统行为**：在系统内 **快速检索并匹配** 与申报课题最相关的 **科研团队**。
- **结果展示**：展示 **匹配到的科研团队（如前 6 名）**，每个团队可展示：
  - 团队配置（成员、设备等）
  - 已完成科研项目
  - 荣誉
  - 效率指标（如平均完成周期、成功率等）
- **团队明细**：**点击每个团队可查看该团队明细**，便于领导全面了解。
- **决策与分发**：领导基于上述信息决定 **将当前科研项目交给哪个团队**，并 **分发给该团队**。

概括：**面向领导的“申报课题 → 匹配团队 → 查看团队明细 → 选定并分发项目”的产教研智能体**。

### 1.2 约束与边界

| 项目 | 说明 |
|------|------|
| 权限与可见性 | 功能入口与按钮可见性由 **Sa-Token 权限控制**，本需求仅关注业务实现，不在此文档中规定具体角色/权限分配。 |
| 入口 | 在现有智能体卡片同级新增「产教研智能体」入口，风格与现有智能体一致。 |
| 输入 | 申报课题（文本，必填）。 |
| 输出 | 匹配的科研团队列表（如 Top 6），每项可进入团队明细；支持将当前项目分发给选定团队。 |

## 2. 技能检索（find-skills）与实现参考

产教研智能体涉及「课题-团队匹配」与「决策支持」，实现时可借助 [find-skills](.cursor/skills/find-skills/SKILL.md) 在开放技能生态中查找与**推荐系统、智能体设计、匹配与排序**相关的技能，作为设计参考（本功能在平台内实现，不直接安装这些技能包）。

### 2.1 使用方式

按 [find-skills SKILL](.cursor/skills/find-skills/SKILL.md) 的用法：

1. **理解需求**：本智能体涉及领域包括推荐/匹配、智能体交互、决策支持。
2. **执行检索**：在项目根目录执行：
   - `npx skills find recommendation` — 推荐系统、推荐引擎设计思路

3. **查看结果**：命令会返回可安装的技能及安装方式（如 `npx skills add <owner/repo@skill>`），可到 [https://skills.sh/](https://skills.sh/) 浏览详情。

### 2.2 检索结果示例（参考）

以下为与「推荐/匹配」相关的检索方向，实际结果以本地执行 `npx skills find <query>` 为准：

## 3. 产品与交互设计要点

### 3.1 工作台入口（实践页）

- **位置**：与现有智能体卡片同一网格内，新增「产教研智能体」卡片。
- **文案建议**：
  - 名称：**产教研智能体**
  - 描述：**根据申报课题匹配科研团队，查看团队明细，辅助领导将项目分发给合适团队**
- **可见性**：由 **Sa-Token 权限** 控制（具备对应菜单/权限的用户才看到入口），实现时仅需按权限校验，无需在业务逻辑中写死角色。

### 3.2 智能体主页面

- **输入区**
  - **申报课题** 输入框（短文本/关键词，可带字数限制与 placeholder）。
  - **「匹配团队」/「开始匹配」** 按钮，触发检索。
- **结果区**
  - 展示 **匹配到的科研团队**（如最多 6 个），每个团队以卡片/行展示：
    - 团队名称、负责人
    - 团队配置摘要（成员、设备等）
    - 已完成项目数量/代表性项目
    - 荣誉、效率指标（如平均周期、成功率等）
  - **点击某一团队**：进入 **团队明细**（成员、项目、荣誉、效率等详情）。
- **分发**
  - 在团队列表或团队明细中，领导可选择 **将当前申报项目分发给该团队**，完成指派。

### 3.3 权限模型（说明）

- 谁可见入口、谁可访问页面与操作，均由 **Sa-Token 菜单/权限** 控制。
- 后端接口对「产教研智能体」相关接口做权限校验；前端根据用户权限渲染入口与按钮即可，无需在业务代码中维护“最高领导人”等角色逻辑。

## 4. 技术设计要点

### 4.1 前端

- **路由**：如 `/practice/industry-education`，与现有实践子路由风格一致；路由 `meta.permission` 使用菜单权限码 **`menu:practice:industry-education`**，由 Sa-Token 与前端权限体系控制访问。
- **实践页卡片**：在实践页的智能体卡片列表中增加「产教研智能体」一项，跳转至上述路由；是否展示该卡片由 **菜单权限 `menu:practice:industry-education`** 决定。
- **菜单与权限码（与 DB 脚本一致）**：
  - 菜单：`menu:practice:industry-education`，路径 `/practice/industry-education`
  - 按钮：`button:practice:industry-education:match`（匹配团队）、`button:practice:industry-education:detail`（查看团队明细）、`button:practice:industry-education:assign`（分发项目）
- **多语言**：在 `locales`（zh-CN、en-US 等）中增加本智能体名称、描述、输入 placeholder、按钮及结果区文案。
- **新页面**：
  - 主页面：申报课题输入、匹配按钮、团队列表/卡片、进入团队明细与分发操作。
  - 团队明细页（或抽屉/弹窗）：展示单个团队的完整信息，并提供「分发给该团队」操作。

### 4.2 后端

- **权限**：所有「产教研智能体」相关接口做 **Sa-Token 权限校验**，无权限返回 403；不在业务代码中写死角色类型。
- **匹配接口**
  - 入参：申报课题文本（必填）、可选分页或 limit（默认如 6）。
  - 逻辑：根据课题关键词/语义在系统内检索与「科研团队」相关的数据，排序后取前 N 条。
  - 出参：团队列表，每项含：团队标识、名称、负责人、配置摘要、完成项目数/列表、荣誉、效率指标等（字段依现有数据模型扩展）。
- **团队明细接口**
  - 入参：团队 ID。
  - 出参：该团队完整信息（成员、设备、完成项目、荣誉、效率等）。
- **分发接口**
  - 入参：申报项目标识（或当前申报课题对应的项目）、目标团队 ID。
  - 逻辑：将项目与团队关联，完成“分发给该团队”的业务操作。
- **数据来源（需与现有模型对齐）**
  - **团队**：若无独立“科研团队”实体，可暂以项目+项目成员为团队维度，或后续引入科研团队实体。
  - **完成项目、荣誉、效率**：来自项目状态/进度、成果表或扩展字段，统计规则与现有数据一致。

### 4.3 匹配逻辑（推荐/检索思路）

- **输入表征**：申报课题文本 → 关键词抽取或简单向量化（若后续接入 Dify/向量检索可做语义扩展）。
- **候选集**：系统内所有科研团队（或当前以项目为单位的团队）。
- **打分/排序**：关键词与团队名称、项目名称、描述、领域等的匹配度；可叠加效率、荣誉等加权。
- **取 Top N**：按分数降序取前 N 条（如 6 条）返回。

## 5. 前后端编码与数据模型

### 5.1 是否需要新增表？

**结论：最小实现可不新增表；若需“稳定科研团队”实体与荣誉/设备等，建议新增表。**

| 能力 | 现有模型能否支撑 | 说明 |
|------|------------------|------|
| **团队维度** | 可支撑（无独立表） | 当前无“科研团队”表。可以 **项目（project）** 为团队单元：一个项目 = 一支执行团队，`project_member` 为成员，`project.manager_id` 为负责人。匹配时的“候选团队”可为历史/现有项目，或按负责人/成员聚合的虚拟团队。 |
| **完成项目 / 效率** | 可支撑 | 来自 `project`（status、progress、时间）与 `declaration` 的统计，无需新表。 |
| **荣誉** | 当前无 | 系统中无荣誉/成果表。若需展示荣誉：可先占位或从扩展字段取；若业务需要则 **新增表**（如 `team_honor` / `user_honor` 或 user/profile 扩展）。 |
| **分发** | 可支撑 | “分发给该团队”即创建/更新项目并指定负责人与成员；若引入科研团队表，则可为 `project` 增加 `team_id` 表示分配给哪支团队。 |

- **不新增表**：以「项目 + 负责人 + 成员」为团队维度，匹配时用申报课题关键词匹配历史项目的名称、描述、研究方向等；团队明细 = 某负责人或某项目下的成员与项目列表；荣誉可暂不展示或占位；效率用项目统计；分发 = 创建/更新项目并指定 `manager_id` 与成员。
- **新增表（推荐在需要“稳定团队”时）**：若业务上“团队”是跨项目存在的编制，可新增 **科研团队** 相关表（如 `research_team`、`research_team_member`），并可选 `team_honor`、设备等；`project` 增加 `team_id` 表示项目分配给哪支团队，匹配与分发都基于团队 ID。

### 5.2 现有表与接口对应关系（不新增表时）

| 需求 | 数据来源 |
|------|----------|
| 匹配候选集 | `project`（及关联 `declaration` 的 research_topic、research_direction、research_fields） |
| 团队负责人 | `project.manager_id`、`declaration.project_leader` / `project_leader_id` |
| 团队成员 | `project_member`（project_id, user_id, user_name, role） |
| 已完成项目数/效率 | `project.status`、进度与时间统计 |
| 团队明细 | 上述表关联查询 |
| 分发 | 创建新 `project` 并写入 `declaration_id`、`manager_id`，写入 `project_member` |

## 6. 实施顺序建议

1. **菜单与权限**：在权限体系中新增「产教研智能体」菜单及页面所需按钮权限（如匹配、查看明细、分发），由 Sa-Token 控制访问；不在此文档规定具体角色分配。
2. **入口与页面**：新增实践页卡片（按权限显示）、路由及主页面（输入 + 匹配 + 列表）。
3. **匹配与明细接口**：确定团队数据来源，实现匹配接口与团队明细接口。
4. **结果展示与明细**：主页面接好匹配接口，支持点击团队进入明细并展示完整信息。
5. **分发**：实现“分发给该团队”接口与前端操作，完成从决策到指派的闭环。
6. **迭代**：根据反馈调整匹配规则、权重与展示字段。

## 7. 小结

- **需求**：产教研智能体面向领导，提供「输入申报课题 → 快速检索匹配科研团队 → 点击查看团队明细 → 决定并将项目分发给该团队」的服务。
- **权限与可见性**：由 **Sa-Token** 做菜单/权限控制，实现时专注业务逻辑即可。
- **设计**：在实践页新增产教研智能体入口与独立页面，包含匹配、团队列表、团队明细、分发能力；后端提供匹配、明细、分发接口，并与现有数据模型对齐。
- **技能检索**：实现前可按 [find-skills](.cursor/skills/find-skills/SKILL.md) 执行 `npx skills find recommendation` 等检索，参考 [skills.sh](https://skills.sh/) 上的推荐/智能体设计类技能（见第 2 节）。
- **数据模型**：最小实现 **可不新增表**，以项目+成员为团队维度；若需稳定“科研团队”实体与荣誉等，再考虑新增表（见第 5 节）。

如需下一步，可从「菜单与权限脚本 + 路由与占位页 + 匹配接口」开始实现，再迭代明细与分发。
