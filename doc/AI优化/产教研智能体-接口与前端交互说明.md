# 产教研智能体 - 接口逻辑与前端交互说明

本文档说明产教研智能体中 **匹配团队**、**团队明细**、**分发** 三个接口的后端逻辑及前端交互细节。

---

## 一、接口总览

| 能力     | 方法 | 路径 | 说明 |
|----------|------|------|------|
| 匹配团队 | POST | `/api/industry-education/teams/match` | 按关键词检索科研团队（以项目为团队单元） |
| 团队明细 | GET  | `/api/industry-education/teams/{id}` | 根据团队 ID 获取成员、项目、效率/荣誉占位 |
| 分发     | POST | `/api/industry-education/assign`     | 将申报分发给目标团队，创建新项目并复制负责人与成员 |

---

## 二、匹配团队

### 2.1 后端逻辑

- **入参**：`TeamMatchReq`
  - `keyword`：申报课题/研究方向关键词（可选，空则仅按项目可见性取列表）
  - `limit`：返回条数上限，默认 6，最大 20
- **处理流程**：
  1. **申报关键词匹配**（若有 keyword）  
     调用 `DeclarationRepo.findIdsByKeywordForMatch(keyword, 200)`：在 `declaration` 表中对 **研究课题（research_topic）**、**研究方向（research_direction）**、**研究内容摘要（content_summary）** 做 `LIKE %keyword%` 检索，取最多 200 条申报 ID（按提交时间倒序）。不做数据权限过滤，仅用于扩大候选集。
  2. **项目筛选**  
     调用 `ProjectRepo.findForIndustryEducationMatch(declarationIds, keyword, limit)`：
     - 只查未删除项目（`is_deleted = 0`）。
     - **数据权限**：当前用户仅能看见自己创建、或任负责人、或任成员的项目（与项目列表一致）。
     - 条件为「申报 ID 在 declarationIds 中 **或** 项目名称/描述 LIKE keyword」；若 keyword 为空则仅按 declarationIds；若 declarationIds 为空则仅按 keyword。  
     结果按 **更新时间倒序**，取前 `limit` 条。
  3. **组装每条团队**  
     对每个项目：解析负责人姓名（先按 `manager_id` 查 `sys_user.real_name`，若无则按 `declaration_id` 取申报的 `project_leader`）、统计成员数（`project_member` 条数）、已完成数（当前项目状态是否为「已完成」则 1 否则 0）、效率占位固定为 `"—"`。
- **出参**：`List<TeamMatchResp>`  
  每项包含：`teamId`（即 projectId）、`teamName`、`leaderName`、`memberCount`、`completedCount`、`efficiencyPlaceholder`。

### 2.2 前端交互

- **入口**：产教研页顶部输入区，用户输入申报课题关键词（textarea，0/500 字），点击 **「匹配团队」** 按钮。
- **请求**：`POST /api/industry-education/teams/match`，body：`{ keyword: 输入.trim() 或 undefined, limit: 6 }`。请求期间按钮 `loading` 且 `disabled`。
- **结果展示**：
  - **成功**：下方展示团队卡片列表（最多 6 条），每卡展示：团队名称、负责人、成员数、已完成、效率占位，以及「查看明细」「分发给该团队」按钮。
  - **失败**：在输入区下方显示 `error-tip`，列表置空。
- **空状态**：未点过匹配时提示「输入申报课题并点击「匹配团队」」；已匹配但结果为 0 条时提示「暂无匹配团队，请尝试其他关键词」。

## 三、团队明细

### 3.1 后端逻辑

- **入参**：路径参数 `id`，即团队 ID（实际为 **projectId**）。
- **处理流程**：
  1. 按 ID 查项目：`ProjectRepo.findById(teamId)`（带数据权限，与项目列表一致）。不存在则返回 `null`。
  2. 解析负责人姓名：逻辑与匹配团队相同（`manager_id` → 用户真实姓名，否则申报的 `project_leader`）。
  3. 查成员：`ProjectMemberRepo.findByProjectId(teamId)`，转为 `TeamMemberResp`（userId、userName、role）。
  4. 当前设计下「团队 = 一个项目」，关联项目列表仅包含该项目本身，状态描述由 `ProjectStatus` 枚举转文案（如「进行中」「已完成」）。
  5. 效率、荣誉为占位字段，固定返回 `"—"`。
- **出参**：`TeamDetailResp`（或 null）  
  含：teamId、teamName、leaderName、members、projects、efficiencyPlaceholder、honorsPlaceholder。

### 3.2 前端交互

- **入口**：
  - 在团队卡片上点击整卡或「查看明细」按钮；
  - 或在已打开的团队明细抽屉内再点「分发给该团队」时，会先弹出分发弹窗，此时目标团队已确定（即当前明细的 teamId）。
- **请求**：打开抽屉时发 `GET /api/industry-education/teams/{id}`。抽屉内先显示「加载中」，再根据结果渲染或「暂无数据」。
- **展示**：右侧 **el-drawer**（400px），标题「团队明细」。内容：成员列表（姓名、角色）、关联项目列表（项目名、状态）、效率指标（占位）、荣誉（占位）。底部有「分发给该团队」按钮，点击后进入分发流程（见下）。

## 四、分发

### 4.1 后端逻辑

- **入参**：`IndustryEducationAssignReq`
  - `declarationId`：要分发的申报 ID
  - `targetTeamId`：目标团队 ID（即目标项目的 projectId）
- **校验**：
  - 申报必须存在；目标项目必须存在；**该申报尚未关联任何项目**（即 `projectRepo.findByDeclarationId(declarationId)` 为 null），否则抛出业务异常（如「该申报已关联项目，请勿重复分发」）。
- **处理流程**（同一事务）：
  1. **新建项目**  
     - 名称：申报的 `research_topic`（有值）或「申报编号 + 配套项目」；描述取申报的 `content_summary`；`declaration_id` = 当前申报；**负责人** = 目标项目的 `manager_id`；编号生成规则 `PRJ + yyyyMMddHHmmss`；状态「进行中」、进度 0；`created_by`/`updated_by` 为当前登录用户。
  2. **复制成员**  
     查目标项目的所有 `project_member`，为每条在新项目下插入一条成员记录（project_id=新项目 ID，userId、userName、role、join_time 等复制，created_by/updated_by 为当前用户）。
- **出参**：新创建的项目 ID（Long）。

### 4.2 前端交互

- **入口**：
  - 在团队卡片上点击「分发给该团队」；
  - 或在团队明细抽屉底部点击「分发给该团队」。
- **弹窗**：**el-dialog**「分发给该团队」，表单项为 **申报 ID**（`el-input-number`，min=1），必填。用户输入要分发的申报 ID，点「确定」触发请求。
- **请求**：`POST /api/industry-education/assign`，body：`{ declarationId: 输入的数字, targetTeamId: 当前选中的团队 ID }`。请求期间确定按钮 `loading`。
- **结果**：
  - **成功**：`ElMessage.success`「分发成功」，关闭分发弹窗与团队明细抽屉。
  - **失败**：`ElMessage.error` 展示接口返回的 message（如申报不存在、目标团队不存在、该申报已关联项目等）。

## 五、数据模型与权限约定

- **团队维度**：以 **项目（project）** 为团队单元，一个 project 对应一支执行团队；负责人为 `project.manager_id`，成员来自 `project_member`。
- **匹配数据来源**：申报表（research_topic、research_direction、content_summary）、项目表（name、description、declaration_id）；不新增表。
- **权限**：接口层暂不做 Sa-Token 权限注解；项目/申报的可见性由现有 **数据权限** 控制（当前用户创建/负责/参与的项目及关联申报）。前端路由仅 `requiresAuth: true`，不做菜单权限控制时，登录即可访问产教研页并调用上述三接口。
