# 产教研智能体 - 执行计划

基于 [科研团队决策智能体-需求与设计.md](./科研团队决策智能体-需求与设计.md)，前后端实现计划如下。**前端 UI 遵循 [ui-ux-pro-max](file:///c:/Users/jarvan_iv/.cursor/skills/ui-ux-pro-max/SKILL.md) 规范**（可访问性、触控目标、布局与响应式、Vue 栈等）。请您确认后开始实现。

## 一、前置与假设

- **菜单与权限**：已存在脚本 `init_permission_data.sql`、`add_industry_education_agent_menu.sql`，权限码为 `menu:practice:industry-education`、`button:practice:industry-education:match`、`detail`、`assign`。若库中尚未执行，需先执行其一完成菜单与权限初始化。
- **数据模型**：采用「不新增表」方案，以 **项目（project）+ 负责人（manager_id）+ 成员（project_member）** 为团队维度；匹配基于 declaration/project 的 research_topic、name、description 等；荣誉先占位或空。
- **UI 规范**：前端页面与组件按 ui-ux-pro-max 要求：可访问性（对比度、focus、aria）、触控目标 ≥44px、加载/错误反馈、Vue + Element Plus 一致性与间距等。

## 三、阶段 1：后端

### 1.1 模块与分层

- **包路径**：`com.sciz.server` 下沿用现有 DDD 分层。
- **新增**：
  - **interfaces**：`IndustryEducationController`（或 `PracticeIndustryEducationController`）。
  - **application.service**：`IndustryEducationService` + impl，编排匹配、明细、分发。
  - **domain**：DTO（请求/响应）、可复用现有 `Project`/`Declaration`/`ProjectMember` 相关 POJO；若无则新增轻量 DTO。
  - **infrastructure**：不新增表时无需新 Mapper；在现有 `ProjectMapper`、`DeclarationMapper`、`ProjectMemberMapper` 或对应 Repository 上做查询/统计。

### 1.2 接口设计

| 接口 | 方法 | 路径（建议） | 权限码 | 说明 |
|------|------|--------------|--------|------|
| 匹配团队 | GET 或 POST | `/api/practice/industry-education/teams/match` | `menu:practice:industry-education` 或 `button:...:match` | 入参：keyword（申报课题）, limit（默认 6）；出参：团队列表（含负责人、成员数、完成项目数、效率占位等）。 |
| 团队明细 | GET | `/api/practice/industry-education/teams/{id}` | `menu:...` 或 `button:...:detail` | 入参：团队 ID（当前即 projectId）；出参：团队详情（成员列表、项目列表、效率、荣誉占位）。 |
| 分发项目 | POST | `/api/practice/industry-education/assign` | `button:...:assign` | 入参：declarationId（或 projectId）、targetTeamId（即 projectId/负责人维度）；逻辑：创建/更新 project，绑定 declaration、manager_id，写入 project_member。 |

### 1.3 匹配逻辑（最小实现）

- 从 `declaration` 与 `project` 中取 research_topic、name、description、research_direction 等文本字段。
- 关键词：对入参 keyword 做简单分词或按空格切分，与上述字段做 LIKE 或 ILIKE 匹配计数/打分。
- 候选集：按负责人（manager_id）或 project 聚合为“团队”，去重。
- 排序：匹配度 + 可选（完成项目数、进度）简单加权，取 Top N（默认 6）。
- 返回：团队标识（projectId 或 leaderId）、名称（项目名或负责人名）、负责人、成员数、已完成项目数、效率占位（可先返回 0 或占位字段）。

### 1.4 权限与异常

- 所有上述接口在 Controller 层使用 Sa-Token 校验权限（如 `@SaCheckPermission("menu:practice:industry-education")` 等），无权限返回 403。
- 业务异常（如 declaration 不存在、无权限操作）返回统一错误码与 message。

## 五、阶段 3：前端 - 产教研主页面（ui-ux-pro-max）

### 3.1 布局与可访问性

- 页面结构：顶部标题 + 简短说明；输入区（申报课题 + 匹配按钮）；结果区（团队卡片列表或空状态）。
- 遵循 ui-ux-pro-max：**可访问性**（表单项带 label、aria、焦点可见）、**触控目标**（按钮、可点击卡片 ≥44px）、**加载态**（匹配中禁用按钮、loading 或 skeleton）、**错误反馈**（接口失败在表单项或顶部提示，不吞错）。
- 使用项目现有设计变量（如 `var(--gap-*)`）、与现有实践页/仪表板风格统一；卡片使用 Element Plus Card，保证对比度与可读字体（body ≥16px 等）。

### 3.2 输入区

- 申报课题：`el-input`（type="textarea" 或 text），maxlength 与 placeholder 从 i18n 取；label 与输入框关联（for + id）。
- 「匹配团队」按钮：具备 `menu:practice:industry-education` 或 `button:practice:industry-education:match` 时展示；点击后请求匹配接口，请求中按钮 loading、可考虑禁用。

### 3.3 结果区

- 团队列表：最多展示 6 条（或接口返回的条数），每条为**卡片**（el-card 或自定义卡片）：
  - 团队名称、负责人、成员数、已完成项目数、效率占位（如“平均周期：—”）。
  - 操作：**查看明细**（触发抽屉/弹窗）、**分发给该团队**（需具备 `button:...:assign` 时展示）。
- 空状态：未搜索时提示“输入申报课题并点击匹配”；搜索无结果时提示“暂无匹配团队”。
- 列表与卡片需键盘可聚焦、可点击区域足够大（ui-ux-pro-max 触控与焦点要求）。

## 六、阶段 4：前端 - 团队明细与分发

### 4.1 团队明细

- 使用 **el-drawer** 或 **el-dialog** 展示团队详情（与主列表同页，不单独路由）。
- 内容：团队名称、负责人、成员列表（姓名、角色）、已完成/进行中项目列表（名称、状态）、效率指标（占位）、荣誉（占位）。
- 底部操作：「分发给该团队」按钮（权限 `button:practice:industry-education:assign` 时展示）。

### 4.2 分发

- 点击「分发给该团队」时，若当前上下文有「当前申报」或「当前项目」，则调用分发接口（declarationId + targetTeamId）；若无，可先弹窗选择申报单再确认分发。
- 成功：提示成功并关闭抽屉；可选刷新列表或跳转项目列表。失败：提示错误信息（接口返回 message）。
