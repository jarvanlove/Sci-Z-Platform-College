# 产教研智能体 / 站内消息 - 编码检查说明

对本次新增/修改的后端与前端代码做了静态与一致性检查，结论如下。

---

## 一、检查范围

- 站内消息：`MessageController`、`MessageService`/`MessageServiceImpl`、`SysMessage` 实体与 Mapper、DTO。
- WebSocket：`MessageWebSocketConfig`、`MessageWebSocketHandler`、`MessageWebSocketHandshakeInterceptor`、`MessageWebSocketSessionHolder`。
- 产教研：`IndustryEducationServiceImpl` 中 `distribute`、`acceptDistribute`、`rejectDistribute` 及 Controller 新增接口。
- 配置：`WebMvcConfig` 对 `/ws/**` 的排除、`pom.xml` 中 `spring-boot-starter-websocket`。

---

## 二、检查结果（是否存在问题）

### 2.1 Lint / 静态检查

- **结果**：上述相关文件 **未发现** Linter 报错。
- **说明**：依赖与注解、泛型、导入均正常。

### 2.2 数据与实体

- **SysMessage** 继承 `BaseEntity`，具备 `isDeleted`（Integer），getter 为 `getIsDeleted()`；`MessageServiceImpl`、`IndustryEducationServiceImpl` 中对 `getIsDeleted()` 与 `DeleteStatus` 的比较用法正确。
- **Declaration** 在 `acceptDistribute` 中构建时已设置必填字段（number、applicant、department、projectLeader、日期、researchTopic、status 等）；未设置 `workflow_result`、`research_fields` 等可为空的字段，与表结构一致。

### 2.3 API 与参数绑定

- **GET /api/messages**：使用 `MessageListQueryReq` 作为参数且未使用 `@RequestBody`，Spring 会从 **query 参数**（如 `?page=1&size=10&unreadOnly=false`）绑定，行为符合预期。
- **PUT /api/messages/read-all**：路径与 `GET /api/messages/{id}` 无冲突（方法不同，且 `read-all` 为字面量）。

### 2.4 WebSocket

- 握手阶段通过 **query 的 token** 校验，并将 `userId` 写入 `attributes`；Handler 在 `afterConnectionEstablished` 中从 `attributes` 取 `userId` 并注册会话，逻辑一致。
- `/ws/**` 已在 `WebMvcConfig` 的 `excludePathPatterns` 中排除，避免 HTTP 鉴权拦截握手。

### 2.5 事务与依赖

- `distribute`、`acceptDistribute`、`rejectDistribute` 均标注 `@Transactional(rollbackFor = Exception.class)`，创建消息、申报、项目、成员、知识库及更新消息在同一事务内，符合预期。
- `KnowledgeService.create` 在 accept 流程中若失败仅打日志并继续，不阻塞申报与项目创建；可根据需要后续改为严格失败回滚。

### 2.6 建议后续可做（非必须）

- **GET /api/messages**：若前端不传 `page`/`size`，会使用 `MessageListQueryReq` 的默认值（page=1, size=10）；若需限制最大 `size`，已在 `getSize()` 中做 `Math.min(size, 100)`，无需改。
- **WebSocket**：生产环境建议将 `setAllowedOriginPatterns("*")` 收窄为实际前端域名。
- **Sa-Token**：握手时使用的 `StpUtil.getLoginIdByToken(token)` 需确保当前 Sa-Token 版本支持；若遇问题可查 [Sa-Token 文档](https://sa-token.cc)。

---

## 三、结论

- **是否存在问题**：当前检查下 **未发现** 必须修复的错误；Lint 通过，实体与 API、WebSocket、事务与配置用法一致。
- **文档**：已新增 `doc/Claude-Code-CLI-使用指南.md`，便于新用户使用 Claude Code CLI 常用命令。
