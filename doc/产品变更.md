# Sci-Z Platform ToC 产品变更方案

## 一、总体目标

将 Sci-Z Platform 从**管理型系统（ToB）**全面转换为**面向消费者的产品（ToC）**，提供现代化的用户体验和视觉冲击力。

## 二、核心变更

### 2.1 页面默认展示

- **默认首页**：前端项目启动后，直接显示 AI 对话页面（`/ai/chat`）
- **无需登录访问**：用户可以查看 AI 对话界面，但需要登录后才能使用全部功能
- **登录后跳转**：登录成功后，仍停留在 AI 对话页面，但功能权限解锁

### 2.2 布局架构

**全新的左侧主导航布局**（参考图 2 设计）：

- **左侧边栏**（固定）：主要功能菜单，包含：
  - 新对话（新建对话入口）
  - AI 对话
  - 学术搜索
  - 科学导航
  - 实践
  - 历史对话（聊天历史）
  - 底部用户信息和设置
- **主内容区**（自适应）：显示当前功能页面
- **顶部 Header**（可选）：根据页面需求显示/隐藏

### 2.3 功能重组

#### 2.3.1 核心 ToC 功能（左侧菜单）

1. **AI 对话** (`/ai/chat`)

   - 默认首页
   - 支持知识库增强对话
   - 支持文件上传
   - 模型选择

2. **学术搜索** (`/literature/search`)

   - 文献检索
   - 学术资源搜索

3. **科学导航** (`/science/navigation`)

   - 科学领域导航
   - 资源分类浏览
   - 学科分类浏览

4. **实践** (`/practice`)
   - **项目管理**：项目列表、项目详情、项目进度
   - **申报管理**：申报列表、申报创建、申报详情
   - **报告管理**：报告列表、报告生成
   - **验收管理**：验收列表、验收详情
   - **知识库管理**：知识库列表、创建、编辑

#### 2.3.2 管理功能（用户登录后可用）

所有原有的 ToB 管理功能整合：

- **仪表板**：整合到"实践"板块或移除（ToC 产品通常不需要仪表板）
- **系统管理**：用户管理、角色权限、系统配置、日志管理、API Key 配置（管理员可见，放在用户下拉菜单的"系统设置"中）
- **用户中心**：个人信息、安全设置（放在用户下拉菜单中）

### 2.4 视觉设计

#### 2.4.1 ToC 产品风格

- **现代化 UI**：

  - 大圆角卡片设计
  - 渐变色彩运用
  - 流畅动画过渡
  - 清晰的信息层级

- **视觉冲击力**：

  - 大号标题和引导文案
  - 丰富的图标和插图
  - 清晰的 CTA（行动按钮）
  - 友好的空状态设计

- **交互体验**：
  - 即时反馈
  - 加载状态清晰
  - 错误提示友好
  - 操作引导明确

#### 2.4.2 布局特点

- **左侧菜单**：

  - 宽度：260-280px（可折叠）
  - 背景：白色或浅色
  - 菜单项：大图标 + 文字
  - 选中状态：明显的高亮显示
  - 底部固定：用户信息和设置

- **主内容区**：
  - 全宽显示（无固定最大宽度限制）
  - 响应式内边距
  - 沉浸式体验（AI 对话等核心功能）

### 2.5 权限控制

#### 2.5.1 未登录用户

- ✅ 可以查看 AI 对话页面界面
- ✅ 可以查看左侧菜单
- ❌ 不能发送消息（提示需要登录）
- ❌ 不能访问其他功能页面（跳转登录）

#### 2.5.2 已登录用户

- ✅ 完整功能访问
- ✅ 根据角色权限显示对应菜单项
- ✅ 管理员可访问系统管理功能

## 三、技术实现

### 3.1 路由配置

```javascript
// 默认路由重定向到 AI对话
{
  path: '/',
  redirect: '/ai/chat'
}

// AI对话作为默认页面，不需要认证即可访问（但功能受限制）
{
  path: '/ai/chat',
  name: 'AIChat',
  component: () => import('@/views/AI/Chat.vue'),
  meta: {
    title: 'AI助手',
    layout: 'toc',  // 统一使用 ToC 布局
    requiresAuth: false,  // 不需要登录即可访问
    showHeader: false  // 不显示顶部Header
  }
}
```

### 3.2 布局组件

- **统一使用 ToCLayout**：
  - 移除 MainLayout 和 ToCLayout 的混合使用
  - 所有功能页面统一使用 ToCLayout
  - ToCLayout 包含左侧主导航和主内容区

### 3.3 左侧导航组件

创建新的 `ToCSidebar.vue`：

- 主要功能菜单（常驻显示）
- 历史对话列表（折叠/展开）
- 底部用户信息区域
- 响应式支持（移动端可收起）

### 3.4 功能整合

- **原有功能重新分类**：
  - 仪表板 → 移除或整合到"实践"板块
  - 项目管理 → 实践板块
  - 申报管理 → 实践板块
  - 报告管理 → 实践板块
  - 验收管理 → 实践板块
  - 知识库管理 → 实践板块
  - 系统管理 → 用户下拉菜单（管理员）
  - 用户中心 → 用户下拉菜单

## 四、实施计划

### 阶段一：布局重构（优先级：高）

1. ✅ 回退代码到 main 分支版本
2. 创建新的 ToCLayout 组件（左侧导航 + 主内容区）
3. 创建新的 ToCSidebar 组件（主导航菜单）
4. 更新路由配置，默认路由指向 AI 对话
5. 更新 App.vue，统一使用 ToCLayout

### 阶段二：核心功能改造（优先级：高）

1. AI 对话页面适配新布局
2. 文献搜索页面适配新布局
3. 知识库列表页面适配新布局
4. 其他核心功能页面适配

### 阶段三：功能整合（优先级：中）

1. 项目管理功能整合到"实践"板块
2. 申报管理功能整合到"实践"板块
3. 报告管理功能整合到"实践"板块
4. 系统管理功能整合到用户菜单

### 阶段四：权限控制优化（优先级：中）

1. 实现未登录用户的受限访问
2. 优化登录引导体验
3. 完善权限检查逻辑

### 阶段五：视觉优化（优先级：中）

1. ToC 风格 UI 组件设计
2. 动画和交互优化
3. 响应式设计完善

## 五、注意事项

1. **兼容性**：确保原有功能不丢失，只是重新组织和展示
2. **用户体验**：登录前后体验要连贯，不能有突兀的跳转
3. **性能**：新布局要保证页面加载速度
4. **响应式**：移动端和桌面端都要良好支持

## 六、参考设计

- **左侧菜单样式**：参考图 2 的左侧导航设计
- **AI 对话页面**：保持现有的对话体验，适配新布局
- **整体风格**：现代化的 ToC 产品风格，具有视觉冲击力
