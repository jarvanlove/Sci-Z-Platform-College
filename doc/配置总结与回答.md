## 📋 问题回答

### 问题 1：结合 AgentSkills.md，CLAUDE.md 要如何配置？

#### 答案

**CLAUDE.md 的作用**：

- 项目顶层指令文件，作为项目的"宪法"
- 提供项目架构概述、技术栈、环境配置等全局上下文
- 跨工具兼容（Cursor、Claude Code、GitHub Copilot）

**CLAUDE.md 与 Rules 的关系**：

| 文件          | 作用         | 优先级 | 内容建议                             |
| ------------- | ------------ | ------ | ------------------------------------ |
| **CLAUDE.md** | 项目顶层指导 | 高     | 项目架构、技术栈、环境配置、关键 API |
| **Rules**     | 具体规范约束 | 中     | 代码风格、文件命名、项目特定配置     |

**你的项目当前状态**：

- ✅ `sci-z-web/CLAUDE.md` - 已存在，包含前端开发规范
- ✅ `sci-z-server/CLAUDE.md` - 已存在，包含后端开发规范

**CLAUDE.md 配置建议**：

1. **保持现有内容**：你的 CLAUDE.md 文件已经包含了详细的开发规范，这是正确的做法。

2. **优化建议**（可选）：

   - 在项目根目录创建统一的 `CLAUDE.md`（项目总览）
   - 子项目的 CLAUDE.md 保持项目特定规范

3. **与 Rules 配合**：
   - CLAUDE.md 提供高层次指导（"项目是什么"）
   - Rules 提供具体规范（"应该怎么做"）
   - 两者互补，不冲突

**配置位置**：

```
项目根目录/
├── CLAUDE.md                    # 项目总览（可选）
├── sci-z-web/
│   └── CLAUDE.md                # 前端规范 ✅ 已存在
└── sci-z-server/
    └── CLAUDE.md                # 后端规范 ✅ 已存在
```

**规则类型分布**：

- `alwaysApply: true`：1 个（notes-rules.mdc）
- `alwaysApply: false`：3 个（智能应用）

### 问题 3：如何根据项目配置 rules、skills、subagents、commands、CLAUDE、MCP？

#### 答案

**配置架构设计**：

### 通用配置 vs 项目特定配置

#### 通用配置（项目根目录 `.cursor/`）

**位置**：项目根目录 `.cursor/`

**特点**：

- 适用于所有项目
- 可以跨项目复用
- 包含通用的编码标准、工作流、工具

**建议配置**：

```
项目根目录/
└── .cursor/
    ├── rules/                      # 通用规则
    │   ├── general-coding-standards.mdc
    │   ├── git-workflow.mdc
    │   └── documentation-standards.mdc
    ├── skills/                     # 通用技能
    │   ├── code-review/
    │   │   └── SKILL.md
    │   └── git-helper/
    │       └── SKILL.md
    ├── agents/                     # 通用子代理
    │   ├── verifier.md
    │   └── debugger.md
    └── commands/                   # 通用命令
        ├── code-review.md
        └── run-tests.md
```

#### 项目特定配置（子项目 `.cursor/`）

**位置**：`sci-z-web/.cursor/` 和 `sci-z-server/.cursor/`

**特点**：

- 仅适用于特定项目
- 包含项目特定的技术栈和规范
- 优先级高于通用配置

**建议配置**：

```
sci-z-web/.cursor/
├── rules/                          # 前端特定规则
│   ├── current-project-rules.mdc  ✅ 已存在
│   ├── vue-component-guidelines.mdc
│   └── api-integration.mdc
├── skills/                         # 前端特定技能
│   └── vue-component-generator/
│       └── SKILL.md
├── agents/                         # 前端特定子代理
│   └── frontend-tester.md
└── commands/                       # 前端特定命令
    └── create-vue-component.md

sci-z-server/.cursor/
├── rules/                          # 后端特定规则
│   ├── current-project-rules.mdc  ✅ 已存在
│   ├── common-rules.mdc           ✅ 已存在
│   ├── notes-rules.mdc            ✅ 已存在
│   ├── ddd-architecture.mdc
│   └── database-rules.mdc
├── skills/                         # 后端特定技能
│   └── java-ddd-generator/
│       └── SKILL.md
├── agents/                         # 后端特定子代理
│   └── test-runner.md
└── commands/                       # 后端特定命令
    └── create-java-module.md
```

#### 6. MCP 配置

**当前状态**：✅ 已配置（Cursor 内置）

**说明**：

- MCP（Model Context Protocol）是 Cursor 内置功能
- 无需额外配置，Cursor 会自动识别和使用
- 可以通过 `Cursor Settings` → `Tools & MCP` → `MCP Servers` 查看已配置的 MCP 服务器

**常用 MCP 服务器**：

- File System MCP - 文件系统操作
- Shell MCP - Shell 命令执行
- GitHub MCP - GitHub 集成（如果配置）

### 配置优先级

```
1. 用户级 Rules（Cursor Settings）          ← 最高优先级
   ↓
2. 项目根目录 CLAUDE.md（如果存在）
   ↓
3. 项目根目录 .cursor/rules/（通用规则）
   ↓
4. 子项目 CLAUDE.md（sci-z-web/CLAUDE.md）
   ↓
5. 子项目 .cursor/rules/（项目特定规则）
   ↓
6. Skills（Agent 按需加载）
   ↓
7. Subagents（Agent 按需调用）
   ↓
8. Commands（用户手动触发）
```
