
interfaces/ → controller, converter
application/ → service (接口 + impl)
domain/pojo/ → entity, mapper, repository, dto/request|response
infrastructure/ → config, shared, external, common

## Hooks 与 Indexing & Docs 配置

### 1. Indexing & Docs（索引与文档）

**作用**：为 Rules、Skills、Subagents、Commands 提供底层上下文——代码库语义索引 + 自定义文档，使 AI 更好理解你的项目。

**配置位置**：Cursor Settings → **Tools & MCP** → **Indexing & Docs**（设置界面，非项目文件）

**建议配置**：

| 项                                | 说明                                                           | 建议                                                         |
| --------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| **Codebase Indexing**             | 查看进度（如 100%、已索引文件数），**Sync** / **Delete Index** | 保持索引完成，定期 **Sync** 以反映最新代码                   |
| **Index New Folders**             | 自动索引新加入的、文件数 &lt; 50,000 的文件夹                  | 建议 **开启**                                                |
| **Ignore Files in .cursorignore** | 排除不需索引的文件（如 `node_modules`、`dist`）                | 编辑 `.cursorignore`，减少噪音、加快索引                     |
| **Docs**                          | 自定义文档（内部 Wiki、API 文档、项目说明）                    | 按需点击 **+ Add Doc**；聊天中可用 **@Add** 将文档加入上下文 |

**与本项目的关系**：Rules、Skills、Subagents、Commands 的执行质量都依赖对代码库和文档的理解，优先确认 Indexing 完成并酌情添加 Docs。

### 2. Hooks（钩子）

**作用**：统一处理并保存 Agent/Subagent 生成的结构化输出（如代码审查报告、测试报告、文档草稿），使生成的文件按约定路径、命名、格式落盘。

**配置位置**：Cursor Settings → **Tools & MCP** → **Hooks**（设置界面；部分版本可能支持 `.cursor/hooks/` 等项目内配置）

**建议**：

- 当前 **Configured Hooks (0)**、**No hook executions yet** 表示尚未配置。
- 当子代理或命令会产生结构化文件（如 `/code-review` 生成报告）时，再在 Hooks 中配置：触发条件、输出目录、命名规则、后处理等。
- 与 **Subagents**、**Commands** 配合使用效果最佳。

**与本项目的关系**：若后续使用验证代理、代码审查代理等子代理并希望报告统一保存到 `reports/` 等目录，可在 Hooks 中配置相应规则。

## CLAUDE.md 配置说明

### CLAUDE.md 的作用

`CLAUDE.md` 是项目的顶层指令文件，作为项目的"宪法"，提供：

1. **项目架构概述** - 整体架构和技术栈
2. **核心技术栈** - 使用的框架和工具
3. **环境配置说明** - 开发环境设置
4. **关键 API 说明** - 重要接口和约定
5. **常见问题修复记录** - 防止 AI 遗忘

### 与 Rules 的关系

| 文件          | 作用                             | 优先级     |
| ------------- | -------------------------------- | ---------- |
| **CLAUDE.md** | 项目顶层指导，提供全局上下文     | 高         |
| **Rules**     | 具体规范约束，定义必须遵守的规则 | 中         |
| **Skills**    | 专业能力扩展，提供可复用的能力   | 低（按需） |

## 注意事项

1. **CLAUDE.md 与 Rules 的关系**：

   - CLAUDE.md 提供高层次指导
   - Rules 提供具体规范约束
   - 两者互补，不冲突

2. **通用 vs 项目特定**：

   - 通用配置放在项目根目录 `.cursor/`
   - 项目特定配置放在子项目 `.cursor/`
   - 通用配置可以被所有项目复用

3. **配置优先级**：

   - 项目特定配置优先于通用配置
   - **Indexing & Docs** 作为底层上下文持续生效，建议优先保证代码库索引完成
   - Rules 的 `alwaysApply: true` 会始终加载
   - Skills 由 Agent 自主决定是否调用
   - **Hooks** 在 Agent/Subagent 生成结构化输出时触发，按需配置

4. **版本控制**：
   - 所有配置文件都应该提交到 Git
   - 避免在配置文件中包含敏感信息
   - 团队共享配置，个人定制使用 `.local` 后缀
