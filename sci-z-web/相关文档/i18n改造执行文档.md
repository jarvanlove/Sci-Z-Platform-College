# 前后端 i18n 国际化改造执行文档

## 📋 文档说明

本文档用于指导前后端进行 i18n 国际化改造，实现多语言支持（中文、英文、日文、韩文）。

**文档版本**: v1.0  
**创建日期**: 2025-01-21  
**适用范围**: 前端 Vue3 项目 + 后端 Java/Spring Boot 项目

---

## 一、最佳实践方案确认

### ✅ 推荐方案：混合策略（方案A + 方案B）

**方案A：枚举值 → 前端翻译**
- 适用于：状态、类型等固定枚举值
- 优点：前后端解耦，前端完全控制翻译，性能好

**方案B：动态文本 → 后端多语言**
- 适用于：操作类型、错误消息、状态描述等动态文本
- 优点：翻译准确，支持后端动态配置，前端无需维护映射表

**不翻译：用户输入内容**
- 适用于：项目名称、申报标题、研究课题等用户输入的业务数据
- 原则：保持原样，不进行翻译

## 二、数据分类与处理策略

### 2.1 数据分类表

| 数据类型 | 示例 | 处理方案 | 优先级 |
|---------|------|---------|--------|
| **枚举值** | `status: 'pending'` | 前端翻译（方案A） | ⭐⭐⭐ 高 |
| **状态码** | `status: 1` | 前端翻译（方案A） | ⭐⭐⭐ 高 |
| **操作类型** | `operation: "登录成功"` | 后端多语言（方案B） | ⭐⭐⭐ 高 |
| **错误消息** | `errorMessage: "用户名或密码错误"` | 后端多语言（方案B） | ⭐⭐⭐ 高 |
| **状态描述** | `statusDescription: "申报中"` | 后端多语言（方案B） | ⭐⭐ 中 |
| **工作流状态** | `workflowStatusDescription: "待处理"` | 后端多语言（方案B） | ⭐⭐ 中 |
| **部门名称** | `departmentName: "计算机学院"` | 后端多语言（方案B） | ⭐⭐ 中 |
| **地理位置** | `location: "北京市"` | 后端多语言（方案B） | ⭐ 低 |
| **项目名称** | `name: "计算机基础"` | 不翻译 | - |
| **研究课题** | `researchTopic: "科学计算..."` | 不翻译 | - |
| **用户输入内容** | 描述、备注等 | 不翻译 | - |

### 2.2 处理策略说明

#### ✅ 前端翻译（方案A）
**适用场景**：
- 状态枚举：`pending`, `generating`, `generated`, `failed`
- 类型枚举：`tech`, `self`, `project`, `independent`
- 权限编码：`menu:project:list`, `btn:system:user:add`
- 日志级别：`INFO`, `ERROR`, `WARN`, `DEBUG`
- 布尔值：`true`, `false`（显示为"是/否"）

**数据格式要求**：
- 后端返回枚举值（code）或数字编码
- 不返回中文文本

#### ✅ 后端多语言（方案B）
**适用场景**：
- 操作类型：登录、创建、删除、更新等操作
- 错误消息：各种业务错误提示
- 状态描述：工作流状态、业务状态描述
- 配置数据：部门名称、分类名称等

**数据格式要求**：
- 后端返回多语言对象或 i18n key
- 前端根据当前语言选择对应文本

#### ❌ 不翻译
**适用场景**：
- 用户输入的业务数据
- 项目名称、申报标题、研究课题
- 用户填写的描述、备注等

**数据格式要求**：
- 保持原样，直接显示

## 三、后端改造规范

### 3.1 枚举值返回规范

#### 3.1.1 状态字段
**改造前**：
```json
{
  "status": "申报中",
  "statusCode": 1
}
```

**改造后**：
```json
{
  "status": "submitting",  // 枚举值，不返回中文
  "statusCode": 1          // 数字编码（可选，用于兼容）
}
```

**枚举值定义**：
- 申报状态：`draft`, `submitting`, `reviewing`, `approved`, `rejected`
- 项目状态：`planning`, `in_progress`, `on_hold`, `completed`, `terminated`
- 报告状态：`pending`, `generating`, `generated`, `failed`
- 用户状态：`enabled`, `disabled`, `locked`

#### 3.1.2 类型字段
**改造前**：
```json
{
  "type": "技术报告",
  "reportType": "技术报告"
}
```

**改造后**：
```json
{
  "type": "tech",        // 枚举值
  "reportType": "tech"   // 枚举值
}
```

**枚举值定义**：
- 报告类型：`tech`, `self`
- 知识库类型：`project`, `independent`
- 文件类型：`document`, `image`, `export`, `other`

### 3.2 多语言数据返回规范

#### 3.2.1 方案一：多语言对象（推荐）

**适用场景**：操作类型、错误消息、状态描述等

**数据格式**：
```json
{
  "operation": {
    "code": "login_success",
    "label": {
      "zh-CN": "登录成功",
      "en-US": "Login Success",
      "ja-JP": "ログイン成功",
      "ko-KR": "로그인 성공"
    }
  },
  "errorMessage": {
    "code": "auth_password_incorrect",
    "label": {
      "zh-CN": "用户名或密码错误",
      "en-US": "Username or password is incorrect",
      "ja-JP": "ユーザー名またはパスワードが正しくありません",
      "ko-KR": "사용자 이름 또는 비밀번호가 올바르지 않습니다"
    }
  }
}
```

**简化版（如果字段名已明确）**：
```json
{
  "operationCode": "login_success",
  "operationLabel": {
    "zh-CN": "登录成功",
    "en-US": "Login Success",
    "ja-JP": "ログイン成功",
    "ko-KR": "로그인 성공"
  }
}
```

#### 3.2.2 方案二：i18n Key（备选）

**适用场景**：如果后端不想维护多语言数据

**数据格式**：
```json
{
  "operation": "operation.login.success",  // i18n key
  "errorMessage": "error.auth.password.incorrect"  // i18n key
}
```

**要求**：
- 前后端需要约定 i18n key 命名规范
- 前端需要维护对应的翻译文件

### 3.4 后端实现步骤

#### 步骤1：定义枚举常量类
```java
// 申报状态枚举
public enum DeclarationStatus {
    DRAFT("draft", "草稿"),
    SUBMITTING("submitting", "申报中"),
    REVIEWING("reviewing", "审核中"),
    APPROVED("approved", "已通过"),
    REJECTED("rejected", "已拒绝");
    
    private final String code;
    private final String defaultLabel;
}

// 项目状态枚举
public enum ProjectStatus {
    PLANNING("planning", "规划中"),
    IN_PROGRESS("in_progress", "进行中"),
    ON_HOLD("on_hold", "暂停"),
    COMPLETED("completed", "已完成"),
    TERMINATED("terminated", "已终止");
    
    private final String code;
    private final String defaultLabel;
}
```

#### 步骤2：创建多语言服务
```java
// 多语言服务接口
public interface I18nService {
    /**
     * 获取多语言文本
     * @param code 文本编码
     * @param locale 语言代码（zh-CN, en-US, ja-JP, ko-KR）
     * @return 翻译后的文本
     */
    String getText(String code, String locale);
    
    /**
     * 获取多语言对象
     * @param code 文本编码
     * @return 多语言对象 {zh-CN: "...", en-US: "...", ...}
     */
    Map<String, String> getI18nMap(String code);
}
```

#### 步骤3：改造实体类
```java
// 改造前
public class Declaration {
    private String status;  // "申报中"
    private String statusDescription;  // "申报中"
}

// 改造后
public class Declaration {
    private String status;  // "submitting" (枚举值)
    private I18nText statusDescription;  // 多语言对象
}

// 多语言文本类
public class I18nText {
    private String code;  // "declaration.status.submitting"
    private Map<String, String> label;  // {zh-CN: "申报中", en-US: "Submitting", ...}
}
```

#### 步骤4：改造响应DTO
```java
// 改造前
public class DeclarationDTO {
    private String status;  // "申报中"
    private String operation;  // "创建申报"
}

// 改造后
public class DeclarationDTO {
    private String status;  // "submitting"
    private I18nText operation;  // 多语言对象
}
```

#### 步骤5：改造Service层
```java
// 改造前
declaration.setStatus("申报中");
declaration.setOperation("创建申报");

// 改造后
declaration.setStatus(DeclarationStatus.SUBMITTING.getCode());
declaration.setOperation(i18nService.getI18nText("operation.declaration.create"));
```

#### 步骤6：改造Controller层
```java
// 在响应头或请求参数中获取语言
@GetMapping("/list")
public Response<List<DeclarationDTO>> getList(
    @RequestHeader(value = "Accept-Language", defaultValue = "zh-CN") String locale
) {
    // 根据语言返回对应的多语言数据
    List<DeclarationDTO> list = service.getList();
    // 如果使用方案二（i18n key），直接返回 key
    // 如果使用方案一（多语言对象），返回完整的多语言对象
    return Response.success(list);
}
```

### 3.5 后端数据库改造（可选）

#### 方案A：不改造数据库（推荐）
- 数据库仍存储中文或枚举值
- 在 Service 层转换为多语言对象
- 优点：不改动数据库结构

#### 方案B：改造数据库
- 新增多语言字段表
- 存储多语言数据
- 优点：支持动态配置
- 缺点：数据库结构复杂

**建议**：先采用方案A，后续根据需求考虑方案B。

```vue

<script>
const getI18nText = (i18nData) => {
  if (typeof i18nData === 'string') {
    // 如果是字符串，可能是 i18n key
    return t(i18nData)
  }
  if (i18nData && i18nData.label) {
    // 如果是多语言对象
    return i18nData.label[currentLocale] || i18nData.label['zh-CN']
  }
  return i18nData || '-'
}
</script>
```

## 五、数据格式规范

- 使用小写字母

| 中文 | 枚举值 | 数字编码 |

**报告状态**：

### 5.2 多语言对象格式规范

```json
{
  "code": "operation.login.success",
  "label": {
    "zh-CN": "登录成功",

    "ja-JP": "ログイン成功",
    "ko-KR": "로그인 성공"
  }
```

## 七、前后端协作规范

### 7.1 接口文档规范

#### 7.1.1 枚举值字段
在接口文档中明确标注：
```yaml
status:
  type: string
  enum: [draft, submitting, reviewing, approved, rejected]
  description: 申报状态（枚举值，前端负责翻译）
  example: "submitting"
```

#### 7.1.2 多语言字段
在接口文档中明确标注：
```yaml
operation:
  type: object
  description: 操作类型（多语言对象）
  properties:
    code:
      type: string
      example: "operation.login.success"
    label:
      type: object
      properties:
        zh-CN:
          type: string
          example: "登录成功"
        en-US:
          type: string
          example: "Login Success"
        ja-JP:
          type: string
          example: "ログイン成功"
        ko-KR:
          type: string
          example: "로그인 성공"
```

## 八、注意事项

### 8.1 兼容性处理

#### 8.1.1 向后兼容
- 改造过程中，后端可能同时返回新旧格式
- 前端需要兼容两种格式
- 逐步迁移，避免一次性改造

#### 8.1.2 数据迁移
- 历史数据可能需要迁移
- 制定数据迁移方案
- 确保不影响现有功能

### 8.2 性能考虑

#### 8.2.1 翻译性能
- 枚举值翻译：前端缓存翻译结果
- 多语言数据：后端缓存多语言配置
- 避免频繁查询数据库

#### 8.2.2 数据量考虑
- 多语言对象会增加响应数据量
- 考虑使用 i18n key 方案减少数据量
- 或使用压缩传输

### 8.3 错误处理

#### 8.3.1 翻译缺失
- 如果翻译缺失，显示原始值或 code
- 记录日志，便于排查
- 提供回退机制

#### 8.3.2 数据格式错误
- 验证多语言对象格式
- 提供默认值
- 错误时显示原始数据

## 十、附录

### 10.1 枚举值完整对照表

**申报状态**：
- `draft` - 草稿
- `submitting` - 申报中
- `reviewing` - 审核中
- `approved` - 已通过
- `rejected` - 已拒绝

**项目状态**：
- `planning` - 规划中
- `in_progress` - 进行中
- `on_hold` - 暂停
- `completed` - 已完成
- `terminated` - 已终止

**报告状态**：
- `pending` - 待生成
- `generating` - 生成中
- `generated` - 已生成
- `failed` - 生成失败

**报告类型**：
- `tech` - 技术报告
- `self` - 自查报告

**日志级别**：
- `INFO` - 信息
- `WARN` - 警告
- `ERROR` - 错误
- `DEBUG` - 调试

### 10.2 多语言 Code 命名规范示例

**操作类型**：
- `operation.login.success` - 登录成功
- `operation.login.failed` - 登录失败
- `operation.declaration.create` - 创建申报
- `operation.declaration.update` - 更新申报
- `operation.declaration.delete` - 删除申报
- `operation.project.create` - 创建项目
- `operation.project.update` - 更新项目
- `operation.project.delete` - 删除项目

**错误消息**：
- `error.auth.password.incorrect` - 用户名或密码错误
- `error.auth.token.expired` - Token 已过期
- `error.auth.permission.denied` - 权限不足
- `error.validation.required` - 必填项不能为空
- `error.validation.format.invalid` - 格式不正确

**工作流状态**：
- `workflow.status.pending` - 待处理
- `workflow.status.running` - 处理中
- `workflow.status.completed` - 已完成
- `workflow.status.failed` - 失败
